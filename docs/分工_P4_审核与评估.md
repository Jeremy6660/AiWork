## 四、核心设计思路（先理解再写代码）

### 4.1 三层审核怎么分三级（不是平级，是递进）

| 层级 | 做什么 | 怎么实现 | 成本 |
|---|---|---|---|
| **L1 规则引擎** | 硬约束：违禁词、格式错误、来源引用是否真实存在于知识列表、字数够不够 | 纯 Python 正则 + 字符串匹配，**不调 API** | 零成本 |
| **L2 知识锚定比对** | 把生成内容的每一个事实断言，和传入的知识列表逐条比对。生成内容里「没有知识依据」的句子 = 潜在幻觉 | 调 1 次 LLM API（单模型，便宜的就行），让它做「逐句事实核查」。喂 prompt：「以下是唯一可信的知识素材，请逐句检查生成内容中是否有无依据的断言」 | 中等 |
| **L3 三模型异构投票** | 只有 L2 判定「高风险」（无依据句子比例 > 某阈值）时才触发。3 家不同厂商的模型各自独立判断「这段内容是否事实正确」，取多数 | 并行调 DeepSeek + 通义 + Kimi，各自输出 pass/fail + 理由 | 高成本 |

> 这个分级触发机制本身就是创新点。研究方案里算过了：90% 内容 L1+L2 搞定，只有 10% 触发 L3——省钱又快。

### 4.2 幻觉分数怎么算（必须有指标，不能瞎说"5%以下"）

定义 3 个可复现指标：

```python
幻觉分数 = max(
    事实性错误率,   # 生成内容中有几条事实与知识素材矛盾 / 总事实断言数
    无依据陈述率,   # 生成内容中有几条句子找不到来源支撑 / 总句子数
    1 - 可溯源率    # 生成内容中多少比例的事实可以在知识列表中找到直接依据
)
```

用 P2 提供的 QA 测试集跑评测，得出数值。**指标定义清楚→结果可复现→<5% 才有说服力**。

### 4.3 效果评估闭环怎么跑

这是官方明确要求的：「基于学习效果评估结果与学员交互行为反馈，实现动态优化」。

你们的闭环逻辑：
1. **内容评估**（`evaluator.py`）：对生成内容打分 —— 事实性、专业性、可读性、与画像匹配度，4 个维度各 0-1 分。
2. **评估结论 → 反馈给 Orchestrator**：审核不通过 → 带修改建议回炉重生成；某项维度得分低 → 给针对性的优化方向。
3. **仿真验证**：因为没真实学员，用 LLM 模拟不同水平的「虚拟学员」，对他们推送内容，模拟他们的学习反馈（「太难了」「看不懂 XX 术语」「这个我会了可以跳过」），把这些反馈灌回系统验证闭环。

## 五、七周计划

### 第 1 周（7/17–7/23）★骨架周★ 交 stub

### 第 2 周（7/24–7/30）L1 规则引擎 + L2 知识锚定
- [ ] **L1 规则引擎**（纯 Python，不调 API）：
  - 来源校验：生成内容的 `引用来源` 列表是否 ≤ 传入的知识列表。
  - 格式校验：Markdown 格式是否正常、有无乱码。
  - 长度校验：正文是否过短（< 100 字 = 太敷衍）。
  - 违禁词检查：维护一个简单的违禁词列表 `["据我所知", "可能", "大概", "一般认为"]` ——这些词是低质量/不确定的标志。
  - 输出：pass / fail + 具体错误描述。
- [ ] **L2 知识锚定比对**（调 1 次 LLM API）：
  - 写 prompt：给 LLM 喂「知识素材（知识列表）」+「待核查内容（培训内容正文）」，要求逐句标注：①此句有依据（来源 X）②此句无依据（潜在幻觉）③此句与素材矛盾。
  - 分析 L2 返回结果，计算高风险判定：无依据句子比例 > 30% → 触发 L3。
- [ ] 实现 `review_content()` 的主体逻辑：依次调 L1 → L2，L2 判高风险时调 L3（L3 下周做）。

### 第 3 周（7/31–8/6）L3 三模型异构投票
- [ ] **选 3 家 API**：DeepSeek + 通义千问 + Kimi（三家里选你最熟悉的做主力），确保每家能单独调通。
- [ ] **L3 投票逻辑**：
  - 给每个模型同样的 prompt：「你是制造业培训内容审核专家。以下是唯一的可信知识素材：{知识列表}。请判断下面培训内容是否事实正确，输出 pass 或 fail，并给出理由。」
  - 投票规则：3 票中 ≥2 票 pass → 通过；否则不通过。理由汇总到 `修改建议`。
  - **防单点故障**：某个 API 挂了怎么办？2/2 投票（降级到两模型）、或者标记「审核结果降级，建议人工复核」——这是工程考量，写进论文/说明就是加分项。
- [ ] 完成 `review_content()` 完整逻辑：L1→L2→(高风险→L3)，输出最终判定。

### 第 4 周（8/7–8/13）幻觉评测基准 + 效果评估
核心目标：**做出评测基准，跑出幻觉率数据**。这是提交时「幻觉率<5%」的唯一依据。

- [ ] **构建评测基准 `eval_benchmark.json`**：
  - 和 P2 配合，用 P2 的 QA 测试集（≥50 题）。
  - 每条标注多维度：事实性(答案是否事实正确)、专业性(是否符合制造业专业标准)、可读性(通俗易懂程度)、与画像匹配度(对「入门」水平的学员是否合适)。
  - 格式：`{问题, 参考答案, 依据来源, 目标画像, 评分维度标注}`
- [ ] **跑评测**：用你们的系统对每条 QA 生成内容，过审核，记录幻觉分数。汇总统计整体幻觉率，证明 < 5%。
- [ ] **写 `evaluator.py`**：多维评分函数 `evaluate(培训内容, 知识列表, 画像) -> dict`：
  ```python

      "事实性": 0.95,      # L2 知识锚定的结果
      "专业性": 0.88,      # 调 LLM 打分（术语准确度）
      "可读性": 0.92,      # 调 LLM 打分（通俗度）
      "匹配度": 0.85,      # 难度与画像掌握度的匹配
  ```

### 第 5 周（8/14–8/20）闭环 + 分级触发调优

## 七、踩坑提示

- **「幻觉率<5%」必须有评测数据支撑。** 别写死在代码里说 0.03，评委要问「你这 0.03 怎么算出来的」。P2 给你 QA 测试集，你跑评测出数据，数字才硬。
- **L3 别每条都调。** 3 个模型并行跑一次就是 3 次 API 调用，钱和时间都扛不住。分级触发不光省成本，还是论文级的创新点。
- **三模型中有一个挂了要优雅降级。** 2/2 投票、或者标记降级，别让整个审核崩溃。这是工程健壮性的体现。
- **修改建议要具体。** 别返回「内容有幻觉请修改」这种废话。要精确到「第 3 段提到主轴转速 12000rpm，但知识素材显示上限是 8000rpm，请修正」。具体的修改建议才能让 P3 有效重生成。
- **评测基准的多维标注要花时间。** 50 题 × 4 维度的标注，大概要花 1-2 天。别拖到最后一周。
- **仿真学员脚本用于验证闭环**，不是用于训练。文档里诚实说明「用 LLM 模拟学员交互进行闭环验证」，这本身也是创新（无真实数据场景下的系统验证方法）。
