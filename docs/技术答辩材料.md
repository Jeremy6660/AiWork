## 一、系统架构（1 Orchestrator + 4 Agent）

```
用户输入（岗位 + 主题 + 答题记录）
        │
        ▼
┌─────────────────────────────────┐
│   Orchestrator (orchestrator.py) │  纯 Python 函数编排，无框架依赖
│   共享状态 dict：画像/知识/       │
│   内容/审核/评估/日志            │
└─────────────────────────────────┘
        │
        ├──→ ① 画像 Agent (profile.py)
        │       岗位能力模型 + 贝叶斯连续更新
        │       输出: 技能掌握度、目标技能、推荐难度、学习路径
        │
        ├──→ ② 检索 Agent (retrieval.py)
        │       ChromaDB + 中文 n-gram 哈希向量
        │       输出: 最多3条已验证、可溯源知识
        │
        ├──→ ③ 生成 Agent (generator.py)
        │       知识锁定的 LLM 约束生成
        │       输出: 定制讲义/实操指南/分阶测试题
        │
        ├──→ ④ 审核 Agent (reviewer.py)
        │       L1规则→L2知识锚定→L3异构投票
        │       输出: 幻觉分数、修改建议、通过/驳回
        │
        └──→ ⑤ 评估模块 (evaluator.py)
                单份内容五维诊断
                输出: 事实性/专业性/可读性/匹配度/知识覆盖率
```

**编排逻辑**：最多 2 次重生成 → 3 轮审核。耗尽转人工复核，绝不自动通过。
**代码位置**: [orchestrator.py:MAX_REGENERATIONS=2](orchestrator.py#L16)

## 二、四个核心创新点

### 2.1 可溯源检索（P2 主导）

- **中文 n-gram 哈希向量**：不依赖外部 embedding API，离线可复现
- **同义词扩展**：`量具→卡尺、千分尺、测量`，解决制造业术语多样性
- **可溯源**：每条知识带 `来源定位`（URL/页码），审核可直接验证
- **无兜底**：知识库未覆盖直接拒绝生成，不返回无关内容

**代码位置**: [agents/retrieval.py](agents/retrieval.py), [knowledge_base/embedding.py](knowledge_base/embedding.py)
**证据**: [tests/test_retrieval.py](tests/test_retrieval.py) (8 项测试覆盖正常检索+边界异常)

### 2.2 差异化画像与个性化路径（P3 主导）

- **岗位能力模型**：4 岗位 × 8 技能，基于国标（《数控机床操作工国家职业标准》等）
- **冷启动先验**：新员工安全规范高、专家技能低——合理、可解释
- **贝叶斯连续更新**：`新=旧+0.15×(目标-旧)`，可解释、可复现
- **贪心学习路径**：先修满足 + 掌握度排序 → 资源难度匹配
- **降维/进阶**：学员反馈后即时调整难度

**代码位置**: [agents/profile.py](agents/profile.py#L115), [knowledge_base/skill_ontology.json](knowledge_base/skill_ontology.json)
**证据**: [tests/profile_test_cases.json](tests/profile_test_cases.json) (4 组差异化画像), [tests/3_profile_comparison.json](tests/3_profile_comparison.json) (同一主题→3种资源类型)

**不宣称使用 DKT/BKT**。准确表述：基于岗位能力模型的个性化画像 + 连续答题动态更新。

### 2.3 分级审核与幻觉控制（P4 主导）

**三层审核架构**：

| 层级 | 机制 | 触发条件 | 特点 |
|---|---|---|---|
| L1 规则引擎 | 正则模式匹配 + 字段验证 | 始终执行 | 零成本，毫秒级 |
| L2 知识锚定 | n-gram 相似度（确定性）/ LLM 事实核查 | 始终执行 | 可离线，可回退 |
| L3 异构投票 | DeepSeek/Qwen/GLM 2/3 多数 | 幻觉分数>0.2 且 ENABLE_L3_VOTING=1 | 仅高风险触发 |

**幻觉分数** = (无依据断言数 + 矛盾断言数) / 事实断言总数

**代码位置**: [agents/reviewer.py](agents/reviewer.py#L198)
**证据**: [tests/test_generation_review.py](tests/test_generation_review.py) (6 项审核联调测试)

### 2.4 反馈闭环

```
生成 → L1规则→L2锚定 → [高风险?]→L3投票 → 通过/驳回
                          ↑                        │
                          │      修改建议            │
                          └──── 回炉重生成 ←────────┘ (最多2次)
                                                        │
                                               需人工复核 ← 耗尽
```

**代码位置**: [orchestrator.py:run()](orchestrator.py#L103-L136)
**证据**: [tests/test_orchestrator.py::test_retry_exhaustion_never_auto_passes](tests/test_orchestrator.py#L27)

## 三、数据规模与局限（主动声明）

### 当前规模

| 指标 | 数值 | 说明 |
|---|---|---|
| 岗位数 | 4 | 数控机床操作工/CNC编程员/质检员/焊接工 |
| 每岗位技能数 | 8 | 含难度层级、先修关系、初始先验 |
| 已验证知识条数 | 30 | 全部来自 Haas/Mitutoyo/Sandvik 等公开资料 |
| 评测集规模 | 12 题 | QA pilot 12 题人工复核集 |
| 异构模型 | 3 | DeepSeek/Qwen/GLM（需配置对应 Key） |

### 已知局限

1. **非训练式知识追踪**：画像更新使用简单贝叶斯，未使用 DKT/BKT 等需要大量训练数据的模型。
2. **离线向量为 n-gram 哈希**：语义匹配精度低于 LLM embedding，但胜在零成本、可复现、无网络依赖。
3. **知识库仅覆盖机械加工领域**：30条知识来自3个公开资料，未覆盖焊接/电气/化工等其他制造领域。
4. **评估指标为单份内容诊断**：`evaluator.py` 的综合分只反映单份内容质量，不等同于官方测试集上的总体准确率。
5. **LLM 生成质量受限于模型能力**：DeepSeek v4-flash 对制造业专业术语的理解可能存在偏差。
6. **无鉴权**：Streamlit 界面仅供本地 Demo，不可暴露公网。

## 四、常见追问及证据位置

| 追问 | 回答要点 | 证据 |
|---|---|---|
| 画像凭什么知道新员工安全规范好？ | 岗位能力模型基于国标，安全培训是制造业入职第一步 | [skill_ontology.json](knowledge_base/skill_ontology.json): 数控机床操作工/安全操作规程与防护 初始先验=0.65 |
| 怎么保证生成内容不瞎编？ | 三层防线：(1)提示词锁定知识范围+铁律 (2)生成后引用验证拒绝越界 (3)审核L1+L2+L3 | [generator.py](agents/generator.py): _validate_grounding(), [reviewer.py](agents/reviewer.py): review_content() |
| L3 投票失败了怎么办？ | 双模型降级为 2/2 投票；不足两个则转"需人工复核"；未触发不产生费用 | [reviewer.py:246-255](agents/reviewer.py#L246) |
| 个性化效果怎么证明？ | 同一主题→同一岗位→3组画像→3种不同资源类型 | [3_profile_comparison.json](tests/3_profile_comparison.json) |
| 知识库够不够大？ | 30条已验证知识覆盖4个主题×3个难度层级；重点是"每条可溯源"而非"海量" | [knowledge.json](data/knowledge.json) |
| 没有API Key怎么办？ | 离线确定性模式零依赖运行；所有测试离线通过 | [generator.py](agents/generator.py): _offline_generate() |
| 为什么不用 LangChain？ | 团队约束：4人小组、编码水平有限、只用Python。当前全链路是纯函数调用，无框架锁入 | [CLAUDE.md](CLAUDE.md): 技术栈速查 |
| 适配准确率≥85%怎么验证？ | 用3组不同画像跑同一问题，人工检查生成内容是否真正适配不同水平 | [3_profile_comparison.json](tests/3_profile_comparison.json) + 人工复核 |
