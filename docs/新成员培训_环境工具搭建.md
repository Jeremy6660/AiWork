## 1. VS Code 安装与配置

### 1.1 下载安装

1. 打开 https://code.visualstudio.com/
2. 点 **Download for Windows**，下载 `.exe` 安装包
3. 双击运行，安装过程**这两项必须勾选**：

> ☑ **将 "通过 Code 打开" 操作添加到 Windows 资源管理器文件上下文菜单**
> ☑ **将 "通过 Code 打开" 操作添加到 Windows 资源管理器目录上下文菜单**

其余选项保持默认，一路下一步即可。

> 🍎 macOS：下载 `.zip` 解压后拖进「应用程序」，然后 `Cmd+Shift+P` → 搜 `shell command` → 选 "Install 'code' command in PATH"。

### 1.2 验证安装

打开终端（Win 键 → 输 `cmd` 回车），输入：

```bash
code --version
```

能输出版本号说明装好了。

### 1.3 推荐基础设置

打开 VS Code → 左下角齿轮 → 设置（或 `Ctrl+,`），搜以下项目修改：

| 设置项 | 建议值 | 作用 |
|---|---|---|
| Files: Auto Save | `afterDelay`（1000ms） | 自动保存，防止丢代码 |
| Editor: Font Size | 16 | 看着舒服 |
| Editor: Tab Size | 4 | Python 用 4 空格缩进（PEP8） |
| Editor: Render Whitespace | `all` | 能看到空格和 Tab 的区别 |
| Files: Encoding | `utf8` | 中文不乱码 |

## 2. AI 编程助手安装

本项目靠 AI 辅助写代码（vibe coding），每人至少装一个。**全组统一用 Claude Code**。

### 2.1 第 1 步：安装 Node.js（Claude Code 的前提）

Claude Code 是用 Node.js 写的，必须先装 Node.js ≥ 18。

**Windows：**

1. 打开 https://nodejs.org
2. 下载 **LTS（长期支持版）**，比如 `20.x.x LTS` 或 `22.x.x LTS`
3. 双击 `.msi` 安装包，一路下一步即可
4. 装完**重启终端**，验证：

```bash
node --version    # 比如 v22.12.0
npm --version     # 比如 10.9.0
```

> 🍎 macOS：建议用 Homebrew 装—— `brew install node`。

### 2.2 第 2 步：安装 Claude Code

打开终端（Win+R → 输 `cmd` 回车），输入：

```bash
npm install -g @anthropic-ai/claude-code
```

> 如果遇到权限错误，Windows 上以管理员身份运行终端再执行。

验证：

```bash
claude --version
```

### 2.3 第 3 步：首次启动

```bash
cd %USERPROFILE%\Documents\AiWork    # 进入项目目录（按你们实际路径改）
claude                                # 启动 Claude Code
```

首次启动会弹浏览器，登录 Anthropic 账号（找组长要账号或 API Key）。后续使用见[第 7 节](#7-claude-code-常用命令)。

### 2.4 备选：OpenAI Codex CLI

Claude Code 额度用完时的备选，装法一样：

```bash
npm install -g @openai/codex
```

> **建议**：主力用 Claude Code，它会读取项目 `CLAUDE.md`；使用 Codex 时读取项目 `AGENTS.md`。项目同时维护这两份规则入口。

## 3. Git——全程可视化操作，命令行只在救急时用

> **核心原则：能用鼠标点就不要敲命令。** VS Code 自带的 Git + Git Graph 插件覆盖 90% 的日常操作。遇到看不懂的报错，截图发群里或直接问 Claude Code "我 Git 报这个错怎么办"。

### 3.1 安装 Git for Windows

1. 打开 https://git-scm.com/download/win
2. 下载 **64-bit Git for Windows Setup**
3. 双击安装，**全部默认**一路下一步即可（选项太多不用管）
4. 装完重启 VS Code，左侧栏会出现「源代码管理」图标（树枝状的）

> 🍎 macOS 自带 git，不用装。

### 3.2 仅此一次：告诉 Git 你是谁

装好 Git 之后，**在终端里执行这两行，一辈子只做一次**：

```bash
git config --global user.name "你的名字（拼音或中文）"
git config --global user.email "你的邮箱"
```

### 3.3 第一次拿到项目：克隆到本地

1. 打开 VS Code → 欢迎页 → **"克隆 Git 仓库"**
2. 粘贴组长给的仓库地址
3. 选一个本地文件夹（比如 `Documents\AiWork`）
4. 点确定，等它拉下来

> 或者用命令行（仅此一次）：`git clone <仓库地址>`

### 3.4 每天写代码的标准流程（纯鼠标操作）

#### 第一步：拉取最新代码

打开 VS Code → 左下角点 **「同步更改」** 按钮（两个旋转箭头）——或者直接 `Ctrl+Shift+P` → 搜 "Git: Sync" → 回车。

> **写代码前必须点一次！** 不然别人改了你本地不知道，后面会冲突。

#### 第二步：写代码，看改动

写代码过程中，左侧「源代码管理」图标会自动显示数字——代表你改了几个文件。点进去能看到每个文件的具体改动：绿色是新增，红色是删除。

#### 第三步：暂存 + 提交

1. 左侧「源代码管理」面板里，把想提交的文件点 **`+`**（暂存更改）
2. 或者直接点 **`+`** 全部暂存（通常在「更改」标题右边有个 `+`）
3. 在上面输入框写提交信息（比如 `feat: 写完检索 Agent stub`）
4. 点 **`✓ 提交`** 按钮，完成！

#### 第四步：推送到远程

提交后，左下角会出现 ↑ 数字——表示有几个本地提交没推。点 **「同步更改」** 就推上去了。

> 总结一下每天就四个动作：**拉取 → 改代码 → 加号+输入信息+提交 → 同步更改**。全程鼠标点，不用输一行 Git 命令。

### 3.5 分支操作（用 Git Graph 可视化）

**点左下角当前分支名**（比如 `main`）→ 弹出分支列表 → 选 "创建新分支" → 按阶段起名，例如 `e1-p2-repro` → 回车。创建完自动切过去。

项目分支结构：

```
main ← 永远可运行
  ├── s2-p1-data       ← S2 阶段，成员 P1
  ├── s2-p2-retrieval  ← S2 阶段，成员 P2
  ├── s2-p3-profile    ← S2 阶段，成员 P3
  └── s2-p4-generator  ← S2 阶段，成员 P4
```

**每个人在自己的分支上写，写完再合到 main。** 合并前由指定验收者复现，本阶段值班集成人负责合并；不是永久由组长承包。

### 3.6 用 Git Graph 看历史

按 `Ctrl+Shift+P` → 输 "Git Graph: View Git Graph" → 回车。

会弹出一个漂亮的分支图，能看到：谁在什么时候提交了什么、分支怎么分叉的、代码怎么演进的。比命令行 `git log` 直观 100 倍。

### 3.7 出问题了怎么办

| 情况 | 怎么处理 |
|---|---|
| 忘了先拉取，push 时提示冲突 | **直接把 Claude Code 的报错截图发给 Claude**，让它帮你解 |
| commit 信息写错了 | 左侧「源代码管理」→ 点右上角 `...` → "Commit" → "Undo Last Commit"（撤销提交但保留改动，然后重新提交） |
| 改了不该改的文件想还原 | 在「源代码管理」里右键该文件 → "放弃更改" |
| 想临时切分支但当前改动不想丢 | 左上角 `...` → "Stash" → "Stash (Include Untracked)"，回来时再 "Pop Latest Stash" |
| 看不懂的报错 | **直接截图问 Claude Code**——"Git 报这个错，怎么办"，Claude 会给具体命令 |

> **底线：遇到搞不定的 Git 问题就丢给 Claude Code 解决。** 不用自己死磕命令行。

### 3.8 .gitignore（项目已配好，不用动）

确保项目根目录 `.gitignore` 里有这些（**绝对不能提交的东西**）：

```gitignore
.env                    # API 密钥，死也不能提交！
__pycache__/
*.pyc
.pytest_cache/
.venv/                  # 某些工具会自动创建；项目统一实际使用 venv/
venv/
chroma_db/              # 本地向量库数据
```

## 5. Python 安装与项目环境搭建

> 这一步是新人最容易卡住的地方，我们一步一步来，每一步都会解释"为什么"。

### 5.1 先理解几个概念（用大白话说）

写 Python 代码就像做菜。我们先把厨房和食材搞清楚：

| 概念 | 类比 | 说明 |
|---|---|---|
| **Python** | 燃气灶 | 执行 Python 代码的程序。没装它，`.py` 文件就是纯文本，跑不起来 |
| **pip** | 买菜 App | Python 的包管理器。你敲 `pip install xxx`，它就自动去网上下载别人写好的库 |
| **库/包（Package）** | 现成的料理包 | 别人写好的代码，你直接 import 就能用。比如 `streamlit` 是一个做网页界面的库 |
| **虚拟环境（venv）** | 你家厨房 vs 饭店后厨 | 同一个电脑上可能有多个 Python 项目，每个项目用的库版本不一样。虚拟环境让它们互相隔离，不打架 |
| **requirements.txt** | 购物清单 | 记录这个项目需要哪些库、什么版本。别人拿到清单，一条命令就能装齐 |

> **最关键的理解**：虚拟环境就是一个独立的小隔间。在这个隔间里装的库，其他项目看不见也用不了——这样 A 项目升了库 B 项目不会炸。

### 5.2 第一步：安装 Python 3.12

1. 打开 https://www.python.org/downloads/ ，点那个黄色的大按钮下载
2. 下载完双击 `.exe` 文件开始安装
3. **关键一步来了**——安装界面第一页，底部有一个复选框：

   > ☑ **Add python.exe to PATH**

   **这一项必须勾上！** 这句话的意思是"让终端能找到 Python"。如果不勾，后面你在终端敲 `python`，Windows 会一脸茫然地告诉你"找不到这个命令"。到时候还得重装，非常麻烦。

4. 勾好之后点 **"Install Now"**，等进度条跑完
5. 装完之后，**关掉终端重新开一个**（这步很重要），然后验证：

```bash
python --version
# 屏幕应该输出：Python 3.12.x

pip --version
# 屏幕应该输出：pip 24.x  from C:\...\Python312\...
```

两行都输出正常版本号 → Python 装好了。

> 🍎 macOS：终端执行 `brew install python@3.12` 即可。

### 5.3 第二步：创建虚拟环境

现在我们要给智策育训项目建一个独立的 Python 小隔间。**这个操作每个项目只做一次。**

#### 先搞清楚你的项目在哪个文件夹

打开 VS Code → 用 VS Code 打开项目文件夹（`文件` → `打开文件夹` → 找到 `AiWork` 文件夹 → 确定）。

然后按 `Ctrl+`` (反引号，在 Esc 下面那个键)打开 VS Code 内置终端。终端里输入：

```bash
pwd
```

这行命令的意思是"告诉我当前在哪个文件夹"。如果输出最后是 `AiWork`，说明位置对了。如果不是，先在 VS Code 左侧资源管理器找到项目文件夹，右键 → "在集成终端中打开"。

#### 然后敲这条命令

位置确认无误后，输入：

```bash
python -m venv venv
```

拆开解释一下这条命令在干什么：

- `python` = 用刚才装的 Python
- `-m venv` = 调用 Python 自带的"创建虚拟环境"功能
- `venv` = 项目统一使用的虚拟环境目录名

回车之后，看起来什么都没发生——**正常**。实际上项目文件夹里多了一个 `venv` 文件夹。

> `venv` 已经写进了项目的 `.gitignore`，永远不会被提交到 Git。每个组员在自己电脑上创建自己的 `venv`，互不影响。

### 5.4 第三步：激活虚拟环境

创建完之后，每次新开终端都要激活它，才能进入这个独立小隔间。**这是全流程最容易忘的一步。**

打开 VS Code 的终端（`Ctrl+``），输入：

**Windows CMD（命令提示符）：**
```bash
venv\Scripts\activate
```

**Windows PowerShell：**
```bash
venv\Scripts\Activate.ps1
```

> 怎么区分 CMD 还是 PowerShell？看终端窗口标题。写 `cmd` 或 `命令提示符` 就是 CMD；写 `PowerShell` 或 `pwsh` 就是 PowerShell。

> PowerShell 如果报红字“无法加载文件，因为在此系统上禁止运行脚本”，可只对当前终端进程临时放宽策略：
> ```powershell
> Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
> ```
> 然后重新执行激活命令。关闭当前终端后，该临时策略自动失效。

#### 怎么判断激活成功了？

看终端最左边，如果出现 `(venv)` 字样，就说明已经在这个独立小隔间里了：

```
# 激活前：
C:\Users\xxx\Documents\AiWork>

# 激活后：
(venv) C:\Users\xxx\Documents\AiWork>
```

记住这个 `(venv)` 标记——**每次装库、跑代码之前，必须先看到它。** 如果没看到，就重新敲激活命令。

> 🍎 macOS：`source venv/bin/activate`

#### 一个小贴士：VS Code 自动激活

如果你按 5.5 节选对了 Python 解释器，VS Code 新开的终端会**自动帮你激活**，省去每次手动敲的麻烦。

### 5.5 第四步：安装项目的依赖库

确认终端左边有 `(venv)` 标记，然后敲：

```bash
pip install -r requirements.txt
```

这条命令的意思是：`pip`（买菜 App）按照 `requirements.txt`（购物清单）把项目需要的所有库一个个下载安装好。

你会看到终端哗哗滚屏——这是 pip 在自动下载安装。**滚屏过程中出现黄字警告是正常的**，不用管。只要最后没有出现大红字 `ERROR`，就说明装好了。

验证一下：

```bash
pip list
```

会列出一串已安装的库。看看里面有没有 `streamlit`、`chromadb`、`openai`——有就对了。

> 以后如果确实新增依赖，先由全组确认必要性，再手工更新 `requirements.txt` 的兼容版本区间。不要用 `pip freeze > requirements.txt` 覆盖团队维护的依赖范围。

### 5.6 第五步：VS Code 里选 Python 解释器（重要！）

这是最后一步配置——告诉 VS Code "请用项目 `venv` 里的 Python，别用系统自带的"。

1. 在 VS Code 里打开项目（任意一个 `.py` 文件都行）
2. 看 VS Code **最底部的蓝色状态栏**，右下角有一个位置显示 Python 版本号（比如 `3.12.x`）
3. **直接点那个版本号** → 弹出一个列表，显示你电脑上所有 Python
4. 选路径里带 **`venv`** 的那个，比如：

   ```
   Python 3.12.x ('venv': venv)   ← 选这个！
   ```

5. 选完之后，状态栏的 Python 版本旁边会多出 `('venv': venv)` 字样

选对之后有两个好处：
- VS Code 的代码提示和语法检查会基于你项目实际安装的库
- **新开的终端会自动激活虚拟环境**，不用每次手动敲 `venv\Scripts\activate`

### 5.7 验证全通：跑起来试试

前面的步骤都做完之后，**关掉终端，按 `Ctrl+`` 新开一个**，确认左边自动出现了 `(venv)`，然后：

```bash
streamlit run app.py
```

如果浏览器自动弹出一个本地页面 → 🎉 Python 环境全部配通！

如果没跑通，回头看 5.4（激活了没？）和 5.6（解释器选对了没？）两步，90% 的问题出在这两处。

## 6. 大模型 API 申请与使用

项目离线模式不需要 API Key。真实生成可先配置 DeepSeek；Qwen、GLM 都配置后，才具备验证真实异构投票的外部条件。

### 6.1 通用申请流程（每家大差不差）

1. 打开平台网站，注册账号（用手机号就行）
2. 进「控制台」或「API Keys」页面
3. 点「创建 API Key」→ 复制下来（**只显示一次，立刻保存！**）
4. 把 Key 写到项目 `.env` 文件（见 6.3）

### 6.2 各平台入口一览

| 厂商 | 申请地址 | 模型名 | 备注 |
|---|---|---|---|
| **DeepSeek** | https://platform.deepseek.com/ | `deepseek-v4-flash`（项目默认） | 真实调用前确认账号可用模型 |
| **Qwen（通义千问）** | https://dashscope.aliyun.com/ | `qwen-turbo` / `qwen-plus` | 阿里云，新用户有免费额度 |
| **智谱 GLM** | https://open.bigmodel.cn/ | `glm-4-flash` | 清华系，有免费额度 |

> Key 只由各自账号持有人写入本机 `.env`，不要在群聊、截图、文档或 Git 中传递。

### 6.3 .env 文件怎么写

项目根目录新建 `.env` 文件（右键 → 新建文本文件 → 改名 `.env`）：

```bash
# .env —— 密钥只放这！绝对不提交 Git！
DEEPSEEK_API_KEY=
QWEN_API_KEY=
GLM_API_KEY=
DEEPSEEK_MODEL=deepseek-v4-flash
```

代码里用 `os.getenv()` 读，**绝不硬编码 Key**：

```python
import os
from dotenv import load_dotenv

load_dotenv()                          # 加载 .env
api_key = os.getenv("DEEPSEEK_API_KEY")  # 只读环境变量，不写死
```

## 7. Claude Code 常用命令

在 Claude Code 终端里，输入 `/` 开头的命令。

### 7.1 日常命令速查

| 命令 | 作用 |
|---|---|
| `/help` | 列出所有可用命令 |
| `/clear` | 清空对话，重新开始 |
| `/compact` | 对话太长变慢时，压缩上下文 |
| `/cost` | 看本次对话花了多少 token |
| `/model` | 切换模型（opus / sonnet / haiku） |
| `/status` | 查看当前会话状态 |

### 7.2 权限模式切换

| 模式 | 怎么进 | 说明 |
|---|---|---|
| **普通模式**（默认） | 启动就是 | 每次操作弹确认框 |
| **自动模式** | 对 Claude 说 "auto-approve my commands" | 常规操作自动放行，危险操作仍需确认 |
| **计划模式** | `/plan` 或 `/enter-plan-mode` | AI 只思考不动手，方案等你确认再执行 |

### 7.3 本项目里怎么用 Claude Code

项目根目录放了 `CLAUDE.md` 规则文件，Claude Code 每次启动自动读取。

**新开对话写代码的标准流程：**

1. 打开终端，cd 到项目目录
2. 敲 `claude` 启动
3. 把需求说清楚，比如："请检查
   `src/zhice_yuxun/agents/retrieval.py` 的
   `search_knowledge(question)`，保持接口不变，为未覆盖问题补一个返回空列表的测试"
4. Claude Code 会读 `CLAUDE.md` → 知道只能用 Python、不引入重框架 → 按项目约束写代码
5. 它写完你审查 → 确认无误 → 在 VS Code 里测试跑通

### 7.4 一个实用技巧：贴背景上下文

每次新开对话，如果涉及跨模块修改，可以这样说：

> "请先读 `docs/项目背景.md` 和 `docs/接口约定.md`，然后帮我 xxx"

这样 Claude 就能理解整个项目的背景和接口约束。

当前任务不要凭旧分工猜测。先打开 `docs/当前状态与下一步执行方案.md`，复制对应 P1–P4 的提示词，再交给 AI 执行。
