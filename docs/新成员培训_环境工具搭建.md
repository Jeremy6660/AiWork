## 1. VS Code 安装与配置

### 1.1 下载安装

1. 打开 https://code.visualstudio.com/
2. 点 **Download for Windows**，下载 `.exe` 安装包
3. 双击运行，安装过程**这两项必须勾选**：

> ☑ **将 "通过 Code 打开" 操作添加到 Windows 资源管理器文件上下文菜单**
> ☑ **将 "通过 Code 打开" 操作添加到 Windows 资源管理器目录上下文菜单**

其余选项保持默认，一路下一步即可。

> 🍎 macOS：下载 `.zip` 解压后拖进「应用程序」，然后 `Cmd+Shift+P` → 搜 `shell command` → 选 "Install 'code' command in PATH"。

### 1.2 验证安装

打开终端（Win 键 → 输 `cmd` 回车），输入：

```bash
code --version
```

能输出版本号说明装好了。

### 1.3 推荐基础设置

打开 VS Code → 左下角齿轮 → 设置（或 `Ctrl+,`），搜以下项目修改：

| 设置项 | 建议值 | 作用 |
|---|---|---|
| Files: Auto Save | `afterDelay`（1000ms） | 自动保存，防止丢代码 |
| Editor: Font Size | 16 | 看着舒服 |
| Editor: Tab Size | 4 | Python 用 4 空格缩进（PEP8） |
| Editor: Render Whitespace | `all` | 能看到空格和 Tab 的区别 |
| Files: Encoding | `utf8` | 中文不乱码 |

## 2. AI 编程助手安装

## 3. Git——全程可视化操作，命令行只在救急时用

> **核心原则：能用鼠标点就不要敲命令。** VS Code 自带的 Git + Git Graph 插件覆盖 90% 的日常操作。遇到看不懂的报错，截图发群里或直接问 Claude Code "我 Git 报这个错怎么办"。

### 3.1 安装 Git for Windows

1. 打开 https://git-scm.com/download/win
2. 下载 **64-bit Git for Windows Setup**
3. 双击安装，**全部默认**一路下一步即可（选项太多不用管）
4. 装完重启 VS Code，左侧栏会出现「源代码管理」图标（树枝状的）

> 🍎 macOS 自带 git，不用装。

### 3.2 仅此一次：告诉 Git 你是谁

装好 Git 之后，**在终端里执行这两行，一辈子只做一次**：

```bash
git config --global user.name "你的名字（拼音或中文）"
git config --global user.email "你的邮箱"
```

### 3.3 第一次拿到项目：克隆到本地

1. 打开 VS Code → 欢迎页 → **"克隆 Git 仓库"**
2. 粘贴组长给的仓库地址
3. 选一个本地文件夹（比如 `Documents\AiWork`）
4. 点确定，等它拉下来

> 或者用命令行（仅此一次）：`git clone <仓库地址>`

### 3.4 每天写代码的标准流程（纯鼠标操作）

#### 第一步：拉取最新代码

打开 VS Code → 左下角点 **「同步更改」** 按钮（两个旋转箭头）——或者直接 `Ctrl+Shift+P` → 搜 "Git: Sync" → 回车。

> **写代码前必须点一次！** 不然别人改了你本地不知道，后面会冲突。

#### 第二步：写代码，看改动

写代码过程中，左侧「源代码管理」图标会自动显示数字——代表你改了几个文件。点进去能看到每个文件的具体改动：绿色是新增，红色是删除。

#### 第三步：暂存 + 提交

1. 左侧「源代码管理」面板里，把想提交的文件点 **`+`**（暂存更改）
2. 或者直接点 **`+`** 全部暂存（通常在「更改」标题右边有个 `+`）
3. 在上面输入框写提交信息（比如 `feat: 写完检索 Agent stub`）
4. 点 **`✓ 提交`** 按钮，完成！

#### 第四步：推送到远程

提交后，左下角会出现 ↑ 数字——表示有几个本地提交没推。点 **「同步更改」** 就推上去了。

> 总结一下每天就四个动作：**拉取 → 改代码 → 加号+输入信息+提交 → 同步更改**。全程鼠标点，不用输一行 Git 命令。

### 3.5 分支操作（用 Git Graph 可视化）

**点左下角当前分支名**（比如 `main`）→ 弹出分支列表 → 选 "创建新分支" → 起名 `p2-add-chromadb` → 回车。创建完自动切过去。

项目分支结构：

```
main ← 永远可运行
  ├── s2-a-data       ← S2 阶段，成员 A
  ├── s2-b-retrieval  ← S2 阶段，成员 B
  ├── s2-c-profile    ← S2 阶段，成员 C
  └── s2-d-generator  ← S2 阶段，成员 D
```

**每个人在自己的分支上写，写完再合到 main。** 合并操作让组长来做，组员只负责在自己的分支 push。

### 3.6 用 Git Graph 看历史

按 `Ctrl+Shift+P` → 输 "Git Graph: View Git Graph" → 回车。

会弹出一个漂亮的分支图，能看到：谁在什么时候提交了什么、分支怎么分叉的、代码怎么演进的。比命令行 `git log` 直观 100 倍。

### 3.7 出问题了怎么办

| 情况 | 怎么处理 |
|---|---|
| 忘了先拉取，push 时提示冲突 | **直接把 Claude Code 的报错截图发给 Claude**，让它帮你解 |
| commit 信息写错了 | 左侧「源代码管理」→ 点右上角 `...` → "Commit" → "Undo Last Commit"（撤销提交但保留改动，然后重新提交） |
| 改了不该改的文件想还原 | 在「源代码管理」里右键该文件 → "放弃更改" |
| 想临时切分支但当前改动不想丢 | 左上角 `...` → "Stash" → "Stash (Include Untracked)"，回来时再 "Pop Latest Stash" |
| 看不懂的报错 | **直接截图问 Claude Code**——"Git 报这个错，怎么办"，Claude 会给具体命令 |

> **底线：遇到搞不定的 Git 问题就丢给 Claude Code 解决。** 不用自己死磕命令行。

### 3.8 .gitignore（项目已配好，不用动）

确保项目根目录 `.gitignore` 里有这些（**绝对不能提交的东西**）：

```gitignore
.env                    # API 密钥，死也不能提交！
__pycache__/
*.pyc
.venv/
chroma_db/              # 本地向量库数据
```

## 5. Python 安装与项目环境搭建

### 5.1 安装 Python 3.12

**Windows：**

1. 打开 https://www.python.org/downloads/
2. 下载 **Python 3.12.x**（Windows installer 64-bit）
3. 双击 `.exe`，**第一个界面必须勾选**：

> ☑ **Add python.exe to PATH** ← 这是最关键的一步！忘记勾选后面全是坑

4. 然后点 "Install Now"，等装完
5. **重启终端**，验证：

```bash
python --version    # 期望：Python 3.12.x
pip --version       # 期望：pip 24.x
```

> 🍎 macOS：`brew install python@3.12`

### 5.2 创建虚拟环境（每个项目独立隔离）

打开终端，cd 到项目目录：

```bash
cd %USERPROFILE%\Documents\AiWork
```

> 上面路径改成你实际放项目的路径。

```bash
# 创建虚拟环境（只需一次）
python -m venv .venv
```

创建完后项目目录下会多一个 `.venv` 文件夹（已加入 `.gitignore`，不会提交）。

### 5.3 激活虚拟环境

**这是最容易忘的一步——每次新开终端都要激活！**

**Windows（CMD）：**
```bash
.venv\Scripts\activate
```

**Windows（PowerShell）：**
```bash
.venv\Scripts\Activate.ps1
```

> 如果 PowerShell 报红字 "无法加载文件..."，先执行这一行再激活：
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```

**怎么判断激活成功了？** 终端最左边会显示 `(.venv)`：

```
(.venv) C:\Users\xxx\Documents\AiWork>
```

> 🍎 macOS：`source .venv/bin/activate`

### 5.4 安装项目依赖

确认虚拟环境已激活（左边有 `(.venv)`），然后：

```bash
pip install -r requirements.txt
```

等它装完，没报错就行。

> 以后如果装了新库，更新 requirements.txt：
> ```bash
> pip freeze > requirements.txt
> ```

### 5.5 VS Code 里选 Python 解释器

1. 用 VS Code 打开项目文件夹
2. 按 `Ctrl+Shift+P`
3. 搜 **"Python: Select Interpreter"**
4. 选那个路径里带 `.venv` 的（比如 `Python 3.12.x ('.venv': venv)`）

选对之后，VS Code 里新开的终端会自动激活虚拟环境。

### 6.3 .env 文件怎么写

项目根目录新建 `.env` 文件（右键 → 新建文本文件 → 改名 `.env`）：

```bash
# .env —— 密钥只放这！绝对不提交 Git！
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
MOONSHOT_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

代码里用 `os.getenv()` 读，**绝不硬编码 Key**：

```python
import os
from dotenv import load_dotenv

load_dotenv()                          # 加载 .env
api_key = os.getenv("DEEPSEEK_API_KEY")  # 只读环境变量，不写死
```

### 6.4 Python 调用示例（各平台写法统一）

这些平台都兼容 OpenAI 的 SDK 格式，只是 `base_url` 和 `model` 不同：

```python
from openai import OpenAI

# DeepSeek 示例
client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1"
)

response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "简述数控机床的日常维护要点"}]
)
print(response.choices[0].message.content)
```

各厂商的 `base_url` 对照：

| 厂商 | base_url |
|---|---|
| DeepSeek | `https://api.deepseek.com/v1` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| Kimi | `https://api.moonshot.cn/v1` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |
| 豆包 | `https://ark.cn-beijing.volces.com/api/v3` |

> 当阶段负责模型适配的成员写好统一调用函数后，大家不用记这些，直接调函数就行。

## 7. Claude Code 常用命令

在 Claude Code 终端里，输入 `/` 开头的命令。

### 7.1 日常命令速查

| 命令 | 作用 |
|---|---|
| `/help` | 列出所有可用命令 |
| `/clear` | 清空对话，重新开始 |
| `/compact` | 对话太长变慢时，压缩上下文 |
| `/cost` | 看本次对话花了多少 token |
| `/model` | 切换模型（opus / sonnet / haiku） |
| `/status` | 查看当前会话状态 |

### 7.2 权限模式切换

| 模式 | 怎么进 | 说明 |
|---|---|---|
| **普通模式**（默认） | 启动就是 | 每次操作弹确认框 |
| **自动模式** | 对 Claude 说 "auto-approve my commands" | 常规操作自动放行，危险操作仍需确认 |
| **计划模式** | `/plan` 或 `/enter-plan-mode` | AI 只思考不动手，方案等你确认再执行 |

### 7.3 本项目里怎么用 Claude Code

项目根目录放了 `CLAUDE.md` 规则文件，Claude Code 每次启动自动读取。

**新开对话写代码的标准流程：**

1. 打开终端，cd 到项目目录
2. 敲 `claude` 启动
3. 把需求说清楚，比如："帮我在 `agents/retrieval.py` 里写一个检索函数，输入岗位名+关键字，返回 top-5 最相关的文档片段"
4. Claude Code 会读 `CLAUDE.md` → 知道只能用 Python、不引入重框架 → 按项目约束写代码
5. 它写完你审查 → 确认无误 → 在 VS Code 里测试跑通

### 7.4 一个实用技巧：贴背景上下文

每次新开对话，如果涉及跨模块修改，可以这样说：

> "请先读 `docs/项目背景.md` 和 `docs/接口约定.md`，然后帮我 xxx"

这样 Claude 就能理解整个项目的背景和接口约束。
