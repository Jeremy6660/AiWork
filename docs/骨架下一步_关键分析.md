# 从可运行骨架到可信最小闭环：当前状态与下一步

> 状态日期：2026-07-18。本文记录当前实现边界，不把规划项写成已完成，也不把机器初标结果写成正式实验成绩。

## 一、已经完成的最小闭环

- 公共契约：`contracts.py` 维护知识、画像和培训内容的轻量校验。
- 模型调用：`llm_client.py` 提供 DeepSeek、Qwen、GLM 的 OpenAI 兼容适配器；自动化测试不调用真实 API。
- 知识检索：39 条已验证、带来源定位的知识切片已写入 ChromaDB；中文 n-gram 哈希向量可离线复现；未覆盖问题返回空列表。
- 学员画像：三个岗位的岗位先验、连续答题更新、推荐难度、目标技能与可解释学习路径已经落地。
- 约束生成：支持定制讲义、实操指南、分阶测试题；专业事实必须携带知识 ID；空知识、未核验知识和越界引用会被拒绝。
- 审核与编排：确定性规则、逐条知识锚定、最多两次重新生成、三种终态（通过/需人工复核/失败）已经落地；重试耗尽不会自动通过。
- Streamlit：状态、证据、断言核查、迭代历史、知识盲区、难度曲线、学习路径和学习反馈均可展示。
- 评测管线：52 条机器初标案例可用于验证管线，但默认不能作为正式指标。

## 二、当前最重要的外部阻塞

### 1. 正式指标缺少人工双人复核

`knowledge_base/qa_test_set.json` 当前案例的标注状态为“机器初标，待人工双人复核”。`evaluate_benchmark.py --include-draft` 的输出只能证明评测管线可运行，不能证明正式幻觉率、难度适配准确率或知识覆盖率。

正式报告前必须完成：

1. 两名标注者分别核对问题、岗位、目标难度、预期知识 ID、参考答案和来源定位。
2. 记录分歧并形成仲裁结果。
3. 仅把通过复核的案例标为“已人工复核”。
4. 不带 `--include-draft` 运行评测并保存运行环境、代码版本和结果。

### 2. 真实模型验证受 Key 限制

- 没有 DeepSeek Key 时，系统采用“离线确定性”模式；这不是故障，也不应伪装成真实模型生成。
- Qwen、GLM Key 未到位前，不能声称真实三模型异构投票已完成。
- 即使 Key 到位，联网 smoke test 也应与离线 pytest 分开执行，避免测试产生费用或受网络波动影响。

## 三、下一阶段的最小增量

1. 完成人工双人标注与仲裁，生成第一版正式可复现指标。
2. 若本机已有 DeepSeek Key，单独验证一条真实生成链路并记录模型名、耗时、失败降级状态；不得输出 Key。
3. Qwen、GLM Key 到位后验证高风险内容的真实异构投票，并保留供应商失败与人工复核路径。
4. 继续扩充官方来源知识，但每次入库前必须通过重复 ID、来源定位和验证状态检查。
5. 如实现 `knowledge_base/build_kg.py` 或 `agents/simulated_learner.py`，先按现有契约写最小版本；当前这两个文件仍是规划项。

## 四、可信表述边界

- 可以说：离线确定性最小闭环已跑通，知识和断言均可追溯，失败状态安全收敛。
- 不可以说：52 条机器初标案例证明了 0% 幻觉率或 100% 适配率。
- 可以说：系统已经具备可选异构投票代码路径。
- 不可以说：在缺少 Qwen、GLM Key 时已经完成真实三模型投票。
- 可以说：画像采用岗位先验与连续答题更新。
- 不可以说：项目训练或部署了 DKT、BKT 或任何本地大模型。

## 五、复现命令

```bash
source venv/bin/activate
python -m compileall -q app.py orchestrator.py test_run.py agents knowledge_base tests
pytest -q
python test_run.py
python knowledge_base/evaluate_benchmark.py --include-draft
```

最后一条命令的结果必须标注为“非正式：包含机器初标”。
