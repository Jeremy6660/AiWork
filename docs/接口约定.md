# 接口约定（可信最小闭环 v1）

> 这是全组公共合同。任何字段变更必须同步当阶段值班集成人、所有调用方、测试和本文件。

数据流：**画像 → 已验证知识检索 → 约束生成 → 断言审核 → 内容诊断 → 动态决策**。

规范实现位于 `src/zhice_yuxun/`。新代码使用
`from src.zhice_yuxun.orchestrator import run` 等包内路径；根目录的
`orchestrator.py`、`contracts.py`、`llm_client.py` 只是旧导入兼容层。
本次目录整理未改变下述任何公共字段或函数签名。

## 1. 知识检索 Agent

```python
search_knowledge(question: str) -> list[dict]
```

最多返回 3 条达到相关度阈值且状态为“已验证”的知识：

```json
{
  "知识ID": "CNC-SAFE-001",
  "内容": "知识正文",
  "来源": "原始资料名称",
  "来源定位": "URL、文件页码或章节定位",
  "主题": ["安全操作", "防护门"],
  "验证状态": "已验证",
  "检索分数": 0.82
}
```

- 未覆盖或低于阈值必须返回 `[]`，禁止返回默认无关知识。
- `内容` 与 `来源` 两个旧字段保留，新增字段用于审核与评测。

## 2. 画像 Agent

```python
build_profile(岗位: str, 答题记录: list) -> dict
```

```json
{
  "岗位": "质检员",
  "技能掌握度": {"量具使用与检测": 0.7},
  "目标技能": ["质量记录与追溯"],
  "推荐难度": "入门 | 应用 | 进阶",
  "画像依据": ["岗位能力模型冷启动", "答题更新说明"],
  "学习路径": [
    {
      "技能": "质量记录与追溯",
      "当前掌握度": 0.45,
      "先修技能": ["量具使用与检测"],
      "先修已满足": true,
      "推荐资源类型": "实操指南",
      "推荐原因": "先修技能已满足"
    }
  ]
}
```

- 未知岗位直接报错，不再使用另一个岗位的默认画像。
- 答题记录格式为 `{"技能": str, "正确": bool}`；字段类型错误直接报错。

## 3. 内容生成 Agent

```python
generate_content(画像, 知识列表, 培训主题, 修改建议="") -> dict
```

```json
{
  "类型": "定制讲义 | 实操指南 | 分阶测试题",
  "标题": "字符串",
  "正文": "Markdown；每条专业事实后写 [知识ID]",
  "引用来源": ["来源名称"],
  "引用知识ID": ["CNC-SAFE-001"],
  "生成模式": "DeepSeek:模型名 | 离线确定性 | 离线降级"
}
```

- `培训主题` 为必填参数，解决旧接口无法感知用户问题的问题。
- 空知识、未核验知识或越界引用必须拒绝生成。
- DeepSeek 调用失败时，只有 `ALLOW_OFFLINE_FALLBACK=1` 才允许使用确定性降级内容。

## 4. 审核 Agent

```python
review_content(培训内容, 知识列表) -> dict
```

```json
{
  "通过": true,
  "流程状态": "通过 | 需人工复核 | 失败",
  "幻觉分数": 0.0,
  "修改建议": "具体到断言的修改要求",
  "审核明细": {
    "规则引擎": "pass | fail",
    "知识锚定": "有依据数量/总断言数",
    "模型投票": "未触发 | 已触发：2/3 | 已触发：0/0（无可用供应商）",
    "风险等级": "low | medium | high",
    "投票明细": []
  },
  "断言核查": [
    {"断言": "...", "状态": "有依据 | 无依据 | 矛盾", "依据": "知识ID"}
  ]
}
```

幻觉分数定义为：`(无依据断言数 + 矛盾断言数) / 事实断言总数`。无可核查断言时不得记为零分。

## 5. 内容诊断模块

```python
evaluate(培训内容, 知识列表, 画像) -> dict
```

保留事实性、专业性、可读性、匹配度和综合分，新增 `知识覆盖率`、`指标依据`。
这些值只用于单份内容诊断，不能写成官方测试集上的总体准确率。

## 6. Orchestrator

```python
run(
    岗位,
    答题记录=None,
    question="",
    *,
    反馈模式="",
    progress_callback=None,
) -> dict
```

核心返回字段：

```json
{
  "流程状态": "通过 | 需人工复核 | 失败",
  "失败原因": "",
  "画像": {},
  "知识列表": [],
  "培训内容": {},
  "审核明细": {},
  "断言核查": [],
  "审核通过": true,
  "幻觉分数": 0.0,
  "评估结果": {},
  "重试次数": 0,
  "学习路径": [],
  "迭代历史": [
    {
      "轮次": 1,
      "内容标题": "字符串",
      "正文": "本轮完整 Markdown 正文",
      "资源类型": "定制讲义",
      "生成模式": "离线确定性",
      "审核通过": false,
      "幻觉分数": 0.5,
      "修改建议": "具体建议"
    }
  ],
  "协同日志": []
}
```

- 最多重新生成 2 次、审核 3 轮；`重试次数`只统计实际重新生成。
- `迭代历史[*].正文` 保存每一轮完整正文，供界面展示修改前后内容；旧消费者可忽略该新增字段。
- 审核耗尽后状态必须为“需人工复核”，绝不自动通过。
- “降维解释”和“进阶挑战”通过 `反馈模式` 调整画像难度后重新执行完整闭环。

## 7. 运行策略

- 默认 `GENERATION_MODE=auto`：配置 DeepSeek Key 时真实生成，否则走确定性离线模式。
- 默认 `ENABLE_LLM_REVIEW=0`、`ENABLE_L3_VOTING=0`，避免无提示产生费用。
- L3 开启后，成功响应的独立供应商不足两个时必须返回“需人工复核”。
- `审核明细.模型投票` 必须区分“未触发”与“已触发但无可用供应商/调用失败”；
  已触发时统一以 `已触发：通过数/成功响应数` 开头，并在不足两个供应商时附原因。
- 自动化测试必须离线、确定性运行；联网 smoke test单独执行。
- `test_run.py` 是强制离线验收入口；`scripts/smoke_llm.py` 默认 dry-run，只有 `--execute` 加终端二次确认才允许真实调用。

### 9.1 冻结盲测集

`knowledge_base/qa_test_set.json` 分离的 30 条冻结盲测。每条结构为：

{
  "案例ID": "BLIND-001",
  "类别": "正常表达 | 同义改写 | 场景问题 | 近领域负例 | 跨领域负例",
  "问题": "原始用户问题",

### 9.3 完整链路入口

```python
run_full_chain_evaluation(blind_set_path=None) -> dict
```

```bash
python knowledge_base/evaluate_benchmark.py --blind
```

每条案例必须从原始“问题”进入
`orchestrator.run(岗位, question=问题, 学习场景=学习场景)`，
不得按预期知识 ID 构造生成输入，也不得从开发集借用答案。评测期间强制：

- `GENERATION_MODE=offline`；
- `ALLOW_DRAFT_TASKPKG=1`；
- `ENABLE_LLM_REVIEW=0`；
- `ENABLE_L3_VOTING=0`。

因黄金任务包尚为草稿，输出必须标注
`"数据状态": "非正式（草稿任务包）"`，不得作为正式安全培训或竞赛验收结论。

### 9.4 判定与指标

单条一致判定：

- 期望“命中任务包”：返回结果含任务包，且“流程状态”为“通过”。
- 期望“知识说明”：返回结果无任务包，但旧路径产生了非空培训内容。
- 期望“拒绝”：“流程状态”为“失败”。

汇总指标均可从“明细”重算：

- **任务包检索命中率** = 期望命中任务包且实际返回任务包/流程通过的案例数 ÷ 期望命中任务包的案例数。
- **正确拒绝率** = 期望拒绝且实际流程失败的案例数 ÷ 期望拒绝的案例数。
- **总体一致率** = 实际判定与期望一致的案例数 ÷ 全部案例数。

明细至少包含：案例ID、类别、期望、实际、流程状态、任务包ID（若有）。

### 9.5 历史入口地位

`run_benchmark(include_draft=False)` 和命令行 `--include-draft` 保留用于回归兼容，
其流程会按已有预期知识 ID 取知识后直接调用生成器。该入口统一标记为
**“历史管线自检（已弃用为正式依据）”**，不得用于对外报告正式指标。
