# 接口约定（模块间 JSON 契约）

> 这是全组的「合同」。任何人改自己模块的输入输出前，必须先跟 P1 同步。
> 每个人只需保证：喂进约定的输入 → 吐出约定的输出。内部怎么实现自由发挥。

数据流：**P2 检索 → P3 画像 → P3 生成 → P4 审核**，P1（orchestrator）串起来。

---

## 1. 知识检索 Agent（P2 · `agents/retrieval.py`）

```python
search_knowledge(question: str) -> list[dict]
```

**输入**：`question` — 字符串，一个培训相关问题。

**输出**：列表，最相关的 3 条，每条：

```json
{"内容": "字符串，知识正文", "来源": "字符串，出处（文件名/标准号/页码）"}
```

> 「来源」字段是审核环节做知识锚定比对的依据，**不能为空**。

---

## 2. 画像 Agent（P3 · `agents/profile.py`）

```python
build_profile(岗位: str, 答题记录: list) -> dict
```

**输入**：
- `岗位` — 字符串，如「数控机床操作工」
- `答题记录` — 列表，可为空（冷启动时用岗位先验）

**输出**：

```json
{"岗位": "字符串", "技能掌握度": {"技能名A": 0.7, "技能名B": 0.3}}
```

> 技能掌握度取值 0~1。冷启动（答题记录为空）时用岗位→技能先验填初值。

---

## 3. 内容生成 Agent（P3 · `agents/generator.py`）

```python
generate_content(画像: dict, 知识列表: list) -> dict
```

**输入**：
- `画像` — 上面第 2 步的输出
- `知识列表` — 上面第 1 步的输出（生成时只能基于这些知识，防幻觉）

**输出**：

```json
{
  "类型": "教程 | 实操指南 | 阶梯项目",
  "标题": "字符串",
  "正文": "字符串（Markdown）",
  "引用来源": ["来源1", "来源2"]
}
```

> 生成时**必须只依据传入的知识列表**，并在「引用来源」里标出用到的来源，供审核比对。

---

## 4. 三层审核 Agent（P4 · `agents/reviewer.py`）

```python
review_content(培训内容: dict, 知识列表: list) -> dict
```

**输入**：第 3 步的输出 + 第 1 步的知识列表（作为事实依据）。

**输出**：

```json
{
  "通过": true,
  "幻觉分数": 0.03,
  "修改建议": "字符串，未通过时给出",
  "审核明细": {"规则引擎": "pass", "知识锚定": "pass", "模型投票": "3/3"}
}
```

> `幻觉分数` 0~1，越低越好，目标 < 0.05。未通过时 orchestrator 拿「修改建议」回炉重新生成（动态编排/闭环）。

---

## 5. Orchestrator（P1 · `orchestrator.py`）

把上面 4 步按数据流串起来；审核不通过时带修改建议回到第 3 步重生成（最多重试 N 次）。对外暴露一个函数供 `app.py` 调用：

```python
run(岗位: str, 答题记录: list, question: str) -> dict  # 返回最终通过审核的培训内容 + 审核明细
```
