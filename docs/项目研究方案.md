# 智策育训 · 项目研究与执行方案

> 面向兴智杯（上海云之脑命题）——领域知识个性化生成与多智能体协同决策系统
> 适用团队：4 人小组，主要依靠 vibe coding（借助 AI 编写代码）

---

## 一、项目简介

智策育训是多领域多智能体协同的个性化培训内容自动生成平台，采用 **"1 Orchestrator + 4 Agent"** 架构，覆盖学习者画像构建、知识检索、内容生成至多层级审核全流程。

瞄准制造业培训的三大痛点：
- 培训周期长
- 缺乏个性化
- 大模型幻觉

项目采用 **三层审核机制**（规则引擎硬约束、知识锚定比对、可选三模型异构投票），目标是在人工复核评测集上验证幻觉率是否低于 5%。当前画像采用岗位能力先验与连续答题更新，不训练 DKT；生成资源为定制讲义、实操指南和分阶测试题。

## 二、赛题分析：隐藏约束（很多队伍会忽略）

1. **不提供数据集**，只给了 FineWeb-Edu / EWeb-Edu 两个「教育类通用」参考集。而赛题背景通篇讲 **制造业**。
   - 参考集是通用教育数据，直接用于制造业培训会「水土不服」。
   - 谁能把「制造业领域数据」做扎实，谁就在起跑线赢了一半。

2. **评分维度**（以比赛原始 PDF 为准）：作品完整性(30) + 技术创新性(25) + 用户体验(15) + 实用价值(30)。
   - 个性化没有独立计分栏，但贯穿完整性、用户体验与实用价值，尤其受“适配准确率≥85%”约束。
   - 当前已用岗位先验、连续答题更新和学习路径替代原先仅停留在概念层的 DKT 设想；正式适配效果仍需人工评测。

3. 赛题四大功能明确要求 **效果评估 + 动态优化闭环**。
   - 很多队做不出（因为没有真实学员），却是「系统完整性」核心。
   - 谁能跑通闭环，完整性分数就稳了。

## 三、五大研究方向

### 方向一：制造业领域数据构建与知识锚定（地基，决定上限）

- **领域数据整理 pipeline**：不训练分类模型，优先从设备厂商官方手册等公开来源人工筛选、切片、核验和记录来源定位，再用轻量规则做结构校验。
- **可溯源知识库**：知识锚定要能「比对」，前提是每条知识都有来源(provenance)。建议构建 **带来源标注的知识图谱 + 向量库双索引**：
  - 图谱管结构化的「设备-参数-工序-故障」关系
  - 向量库管非结构化文本
- **时效性**（赛题第二大痛点，原简介未正面回应）：设计知识版本化与「过期检测」机制。这是原方案空白，建议补上，对应一个独立赛题方向。

### 方向二：反幻觉三层审核（王牌，但要防三个反问）

三层审核是好点子，但评委一定追问，先替他们问：

1. **「5% 以下」怎么测出来的？** 没有权威的制造业事实核查基准，数字就站不住。
   - 建议：**把「如何度量幻觉」本身做成研究贡献**——构造带 ground-truth 的制造业 QA/知识测试集，定义可复现指标（事实性错误率、无依据陈述率、可溯源率）。有可信评测方法，5% 才有说服力。
2. **三模型异构投票，成本和延迟怎么办？** 每条内容跑三个大模型，Demo 会很慢很贵。
   - 建议：**分级触发**——先用规则 + 锚定快速过滤，只有「高风险/低置信」内容才升级到三模型投票。既是工程优化也是创新点（自适应审核强度）。
3. **投票如何裁决冲突？** 简单多数还是加权？锚定与投票冲突时听谁的？
   - 建议：做成 **带置信度的证据聚合**，而非硬投票。

### 方向三：岗位画像 + 连续答题更新（跨多个评分项）

必须正视：**训练 DKT 需要大量学员答题交互序列，而项目没有真实制造业员工数据，也禁止训练模型**，因此当前实现不采用 DKT。

- **冷启动解法**：用「岗位能力模型」做先验（岗位→所需技能→初始掌握度先验），再用连续答对/答错记录快速更新。
- **画像→路径的可解释映射**：把技能本体中的先修关系与当前掌握度结合做路径规划，并明确推荐原因。
- **表述边界**：只称「岗位画像 + 知识状态双驱动」，不把轻量规则更新包装成 DKT/BKT 训练结果。

### 方向四：多智能体协同（1 Orchestrator + 4 Agent，做出深度）

大量队伍只做「顺序调用四个 prompt」，评委看多了。差异化研究点：

- **协同的必要性证明**：说清「为什么必须多智能体，而非一个大 prompt 串起来」。做 **消融实验**（单体 vs 多智能体），用数据证明协同带来的质量提升，直接对应「技术创新性」。
- **Orchestrator 的决策机制**：静态流水线 or **动态编排**（根据审核反馈决定重生成/换 Agent/升级审核）？动态编排 + 反馈回路是加分项。
- **Agent 间的黑板/共享记忆**：定义清楚共享什么状态，如何避免信息丢失。

### 方向五：效果评估闭环（系统完整性的分水岭）

赛题明确要「量化评估 + 动态优化」。

- **多维评估指标**：内容侧（事实性、专业性、可读性）、个性化侧（与画像匹配度、路径合理性）、学习侧（仿真学员为后续评测规划项，当前不计入主链路）。
- **闭环**：评估结果如何反哺 Orchestrator 重新生成或调整路径——在 Demo 里演出来，「动态优化」就落地了。

### 战略总结（一句话）

> **王牌是反幻觉（守），但夺分点在个性化闭环和数据地基（攻）。** 把重心从「再堆一层审核」转向「把幻觉度量做成可信基准 + 把个性化冷启动和评估闭环跑通」，因为这三件事同时命中完整性、创新性、用户体验和实用价值。

## 四、技术栈（vibe coding 能搞定的版本）

> 关键认知：**你们不需要训练大模型。** 全程调 API + 检索增强(RAG) + 提示词工程即可覆盖 90% 功能。

| 部分 | 选型 | 为什么 |
|---|---|---|
| 语言 | **只用 Python** | 一门语言，减少混乱 |
| 界面/Demo | **Streamlit** | 不写 HTML/CSS/JS，AI 几行生成网页，录视频够用 |
| 大模型 | **调 API**（当前适配 DeepSeek、Qwen、GLM） | 三家均配置 Key 且调用成功后，才可验证真实异构投票 |
| 知识库检索 | **ChromaDB** | `pip install` 即用的本地向量库，做 RAG/知识锚定 |
| 知识图谱 | **NetworkX 或直接 JSON** | 别碰 Neo4j，弱队会被数据库劝退 |
| 编排 Orchestrator | **纯 Python 函数调用** | 别上 LangGraph 框架；自己写的流程逻辑反而好讲「这是我们的创新」 |

> 原则：**能用一个函数解决的，就不要引入一个框架。** 分数来自「系统跑通 + 效果好」，不是用了多少花哨的库。

## 五、4 人分工（按阶段并行、交叉验收）

产品仍采用 1 Orchestrator + 4 Agent，但 Agent 是产品架构，不是四个人的长期岗位。团队按“契约 → 骨架 → 首条真实链路 → 审核闭环 → 扩展实验 → 评测体验 → 冻结提交”推进。

每个阶段遵守四条规则：

1. 4 人同时领取不同但可并行的交付物。
2. 每项交付物由另一名成员复现和验收，作者不能自验通过。
3. 每阶段都要形成一条可运行、可演示的纵向链路。
4. 阶段退出门槛未满足时，全员先补齐，不让少数人独自掉队。

详细日期、每阶段 P1/P2/P3/P4 任务、验收关系和范围取舍见 `docs/阶段制分工与互验计划.md`，每名成员再按自己的任务书执行。

> 数据流仍是：**检索 → 画像 → 生成 → 审核 → 评估，由 Orchestrator 串联。** 人员会在不同阶段轮换实现、集成、测试和材料职责，因此任何模块都没有永久的单人负责人。

## 六、弱队救命纪律：先搭「能走路的骨架」

4 人弱队最容易翻车的地方——**各写各的，最后一周拼不到一起**。解法：

**第 1 周先做一件事：用假数据把全流程跑通。**

全员先定好每个模块的输入输出（用 JSON 约定，全员认可）：

```
检索Agent:  输入{问题} → 输出{知识列表:[{知识ID, 内容, 来源, 来源定位, 检索分数}]}
画像Agent:  输入{员工岗位, 答题记录} → 输出{技能掌握度, 推荐难度, 学习路径}
生成Agent:  输入{画像, 知识列表, 培训主题, 修改建议} → 输出{培训内容, 引用知识ID, 生成模式}
审核Agent:  输入{培训内容, 知识列表} → 输出{流程状态, 幻觉分数, 断言核查, 修改建议}
```

这一骨架阶段已经完成；当前主链路已替换为真实 ChromaDB 检索、岗位画像、约束生成和确定性审核。后续开发必须在现有闭环上增量推进，不得把系统再描述成全 stub。

## 七、Vibe Coding 提示词技巧（核心生产力）

弱队靠 AI 写代码，**提示词质量 = 代码质量**。

1. **每次开新对话，先「喂全局背景」再提需求。** 别上来就「帮我写个检索功能」。先说清项目是什么、技术栈、文件结构、模块的输入输出。维护一个 `项目背景.md`，每次贴进去。

2. **一次只让 AI 写一个小东西。** 别说「写整个审核系统」，改成「写一个函数 `check_rules(text)`，输入文本，检查是否包含违禁词，返回布尔值」。小步 = 好验证 = 出错好定位。

3. **把接口/契约明确告诉 AI。** 例如：「输入是 `{'岗位':str, '答题记录':list}`，输出必须是 `{'技能':{技能名:0-1分数}}`。」契约明确，AI 就不乱发挥，也方便对接。

4. **要求「可直接运行 + 带示例」的代码。** 加一句：「请附一段 `if __name__=='__main__':` 示例，我复制就能跑。」

5. **报错原封不动贴回去。** 别自己转述。「运行报了这个错：[完整粘贴报错]，帮我修，并解释为什么错。」加「解释为什么」能让你们慢慢学会 debug。

6. **明确要求「最简单能用的方案」。** 弱队最大敌人是过度设计。每次加：「我是新手，请用最简单的方法，不要引入额外的库。」

7. **锁住已经跑通的代码。** AI 常「顺手」改坏能用的代码。加一句：「下面这段已能正常工作，请不要改动，只在此基础上新增功能：[贴代码]」。

8. **让 AI 当老师。** 「写完后用大白话解释每一部分在干嘛，假设我完全不懂。」

### 可复用提示词模板

```
【项目背景】智策育训——制造业个性化培训系统，Python + Streamlit + ChromaDB。
【我负责的模块】知识检索 Agent。
【当前任务】写一个函数 search_knowledge(question)。
【输入】question: 字符串
【输出】列表，每项至少含 {"知识ID": str, "内容": str, "来源": str, "来源定位": str, "验证状态": "已验证", "检索分数": float}
【要求】
- 用 ChromaDB 做向量检索，返回最相关的 3 条
- 我是新手，用最简单的写法，不要引入额外的库
- 附带一段可直接运行的示例
- 写完用大白话解释每一步
```
