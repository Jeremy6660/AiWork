# P2 分工书 — 数据 + 知识检索 Agent

> 你是全组的「地基」。没有你做的知识库，P3 生成就是瞎编，P4 审核也无从比对。
> 官方红线里「知识点覆盖率≥90%、拒绝回答未覆盖问题」这两条的命脉在你手里。
> 每次让 AI 写代码前，先读 `docs/项目背景.md` 和 `docs/接口约定.md`。

## 一、你负责什么（一句话）

从零搭制造业知识库（向量库 ChromaDB + 知识图谱 NetworkX/JSON），每条知识带来源，实现 `search_knowledge(question)`，给 P3 和 P4 喂准确可溯源的知识。

## 三、你的核心产出（文件清单）

1. `data/` —— 收集的原始数据（设备手册片段、国标摘录、工艺规程、安全规范等）。
2. `knowledge_base/build_chromadb.py` —— 建库脚本：把 data/ 里的文本切片 + 向量化 + 写入 ChromaDB。
3. `knowledge_base/build_kg.py` —— 知识图谱脚本：从文本里抽「设备→参数→工序→故障」关系，用 NetworkX 存为 JSON。
4. `agents/retrieval.py` —— 检索 Agent：`search_knowledge(question)`，混合检索向量 + 图谱，返回带来源的 top-3。
5. `knowledge_base/qa_test_set.json` —— ≥50 组制造业 QA 测试集（带答案的来源标注），供 P4 评测幻觉率用。

## 四、七周计划

### 第 1 周（7/17–7/23）★骨架周★ 交假数据 stub
- [ ] **先交 stub**：`search_knowledge(question)` 返回 2 条写死的假知识，格式严格对齐接口约定：
  ```python
  [{"内容": "数控机床主轴转速不得超过 8000rpm，否则加速轴承磨损。", "来源": "GB/T 16462-2020 第5.3节"},
   {"内容": "每日开机前需检查冷却液液位，低于刻度线 1/3 时必须补充。", "来源": "设备操作手册 v3.2 第12页"}]
  ```
- [ ] **让 P1 验证**：P1 写 `orchestrator.py` 时，用你的 stub 能跑通整条链路。

> 这一周你的目标不是做真实数据，是**让接口能跑**。真实数据下周才开始。

### 第 2 周（7/24–7/30）收集数据 + 建向量库
核心目标：**攒出≥50 条有来源的制造业知识条目**，保证接口的第二个返回值从不空。

- [ ] **确定数据范围（先圈 3 个制造业细分方向，别太散）**：
  - 方向 A：数控机床操作（设备手册 + 安全规范，最通用）
  - 方向 B：焊接工艺（国标 + 工艺规程）
  - 方向 C：质量管理/检测（国标 + 检验标准）
  - 来源优先级：国标/行标 > 设备手册 > 工艺规程 > 安全规范 > 技术教材
- [ ] **数据格式统一**：每条数据存成 JSON，字段 `{id, 内容, 来源, 类型, 关键词, 采集日期}`。
  - 「类型」取：设备参数 / 操作规范 / 安全规程 / 故障诊断 / 工艺标准 / 检验标准
  - 「关键词」手动标 3-5 个，图谱建边时用
- [ ] **向量库脚本 `build_chromadb.py`**：
  - 读 data/ 下所有 JSON → 用 `sentence-transformers`（免费小模型）或直接调 DeepSeek 的 embedding API 向量化 → 写入 ChromaDB。
  - 切片策略：每条知识切成 200-500 字的段落，重叠 50 字。
  - 元数据存 `来源` 和 `类型`，检索时能过滤。
- [ ] **检索函数 `search_knowledge()`** 先做最简单的：向量相似度 top-3，直接包装 ChromaDB 的 query。后面再加图谱融合。

### 第 3 周（7/31–8/6）知识图谱 + 双索引检索
- [ ] **图谱脚本 `build_kg.py`**：
  - 实体：设备、部件、参数、工序、故障类型、安全规范。
  - 关系：has_part / has_parameter / has_procedure / causes_fault / regulated_by。
  - 存储：NetworkX 图，导出为 JSON（别碰 Neo4j）。
  - 抽取方式：用 LLM 调 API 从已有知识条目的「内容」字段里抽实体和关系（给 LLM 喂 few-shot prompt），你审核 + 手动修正。**不是全自动，是人机协作。**
- [ ] **混合检索**：改进 `search_knowledge()` —— 向量（语义匹配）+ 图谱（结构匹配），融合排序返回 top-3。
  - 向量得分 × 0.6 + 图谱相关性 × 0.4。图谱相关性：问句里提到的实体在你的图谱中邻居是哪些，相关知识加权。
- [ ] **未覆盖拒绝**：检索得分低于阈值时，返回 `[]` 或标记「知识库暂未覆盖此内容」，而不硬编。（这是官方的明确要求）

### 第 4–5 周（8/7–8/20）补数据 + 测试集 + 持续完善
- [ ] **构建 QA 测试集 `qa_test_set.json`**（≥50 组）：格式 → `{问题, 参考答案, 依据来源, 关联知识条目ID}`。至少 20 组带可验证的事实性 ground-truth（如参数数值、标准号）。这是 P4 测幻觉的基准，也直接支撑「知识点覆盖率≥90%」的指标。
- [ ] **持续补数据到≥80 条**，覆盖 3 个细分方向的常见知识点。关键不是数量，是每条都有来源、都能溯源。
- [ ] **写一个覆盖率自检脚本**：随机抽 20 个制造业培训问题，跑检索，标注「命中/未命中」，计算命中率。目标 ≥90%。
- [ ] 配合 P4：把 QA 测试集交给 P4 做幻觉率评测。

### 第 6 周（8/21–8/27）配合集成 + 写文档
- [ ] 调试自己的检索 Agent，配合 P1 集成，处理接口联调的边界情况（检索为空？返回太多？格式不对？）。
- [ ] 写一份「知识库构建说明」：数据来源列表、构建流程、覆盖率指标。P1 会整合进提交材料。
- [ ] 整理 data/ 和 knowledge_base/ 的 README，让评委能复现你的建库流程。

### 第 7 周（8/28–9/5）收尾
- [ ] 冻结数据（别在最后一周改数据，会导致 QA 测试集和覆盖率数据变动）。
- [ ] 配合 P1 拍视频：演示「输入问题 → 检索返回相关知识点+来源」的过程。
- [ ] 汇总自己的提交物交给 P1。

## 五、接口约定（你只需保证这个函数）

```python
# agents/retrieval.py
def search_knowledge(question: str) -> list[dict]:
    """
    输入: question — 字符串，例如「数控机床主轴最高转速是多少」
    输出: 列表，最相关的 3 条，每条 {"内容": str, "来源": str}
    如果知识库未覆盖，返回空列表 []
    来源字段不能为空！
    """
```

> 来源字段是审核 Agent 做知识锚定比对时的依据——**如果为空，审核就废了**。

## 六、踩坑提示

- **数据不在多，在每条可溯源。** 50 条有来源标注的知识 >> 500 条没来源的。来源是官方评分表里明确要求的关键点。
- **别碰 Neo4j / 数据库。** 图谱用 NetworkX 存 JSON 就行。你是 vibe coding，别给自己加难度。
- **ChromaDB 是本地库**，`pip install chromadb` 即用。做 embedding 优先调 API（DeepSeek embedding），别自己训模型。
- **知识切片别太大。** 每段 200-500 字，检索精度远比一段塞 2000 字高。
- **QA 测试集是给 P4 用的**，务必确保每条答案都有**可独立验证的事实**（参数数值、标准号、操作步骤），不要含模糊的「大致/通常/一般」。
- **不确定的知识不要入库。** 宁可少，不可错。制造业数据错了是安全事故级别的，入库前和队友交叉检查一遍。
