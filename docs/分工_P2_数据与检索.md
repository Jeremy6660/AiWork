## 五、接口约定（你只需保证这个函数）

```python
# agents/retrieval.py
def search_knowledge(question: str) -> list[dict]:
    """
    输入: question — 字符串，例如「数控机床主轴最高转速是多少」
    输出: 列表，最相关的 3 条，每条至少包含
          {"知识ID", "内容", "来源", "来源定位", "主题", "验证状态", "检索分数"}
    如果知识库未覆盖，返回空列表 []
    来源字段不能为空！
    """
```

> 来源字段是审核 Agent 做知识锚定比对时的依据——**如果为空，审核就废了**。

## 六、踩坑提示

- **数据不在多，在每条可溯源。** 50 条有来源标注的知识 >> 500 条没来源的。来源是官方评分表里明确要求的关键点。
- **别碰 Neo4j / 数据库。** 图谱用 NetworkX 存 JSON 就行。你是 vibe coding，别给自己加难度。
- **ChromaDB 是本地库**，当前 embedding 使用项目内纯 Python 中文 n-gram 哈希向量；不训练模型，也不依赖重型本地 embedding 模型。
- **知识切片别太大。** 每段 200-500 字，检索精度远比一段塞 2000 字高。
- **QA 测试集是给 P4 用的**，务必确保每条答案都有**可独立验证的事实**（参数数值、标准号、操作步骤），不要含模糊的「大致/通常/一般」。
- **不确定的知识不要入库。** 宁可少，不可错。制造业数据错了是安全事故级别的，入库前和队友交叉检查一遍。
