## 背景
项目要把生成目标从"围绕知识点写文章"升级为"基于完整培训任务包生成岗位微课"。第一步是数据层：新增 `data/training_tasks.json`（当前已存在一个空骨架，字段齐全，你只需填充内容）。

## 数据纪律（最高优先级，违反即失败）
1. **所有专业陈述必须绑定知识 ID**。知识库在 `data/knowledge.json`，黄金任务可引用 `CNC-SAFE-001/004/009/010`（另有 002/003/005/006/007/008/011/012 可参考）。先读 `data/knowledge.json` 全文，确认每条引用的知识 ID 真实存在、内容吻合。
2. **禁止编造**：现有知识无法支持的设备参数（如主轴转速、电压）、操作规程细节、后果量化（如"3 秒内停止"）、标准号等，一律留空并写入 `来源缺口` 数组（格式：{"字段": "操作步骤[1].判定标准", "缺失": "门联锁检查的具体判定指标", "建议来源": "本机操作手册/供应商资料"}），不得虚构。
3. **验证状态保持 "草稿"**，不得自行改为"已核验"。
4. 措辞要与知识条目内容一致：例如 CNC-SAFE-010 只说"联锁钥匙无弯曲或错位、紧固件齐全、联锁机构无阻塞或偏移"，判定标准只能写这些，不能加"用扭矩扳手验证"之类知识库没有的细节。

## 结构要求（严格按骨架字段）
- `学习目标`：≥1 条，每条含 行为/条件/标准/引用知识ID 四字段；标准必须是可观察可考核的（如"关键项目无遗漏；发现异常时停止启动并上报"）。
- `操作步骤`：4~8 步，按真实开机前检查逻辑排序（建议：①防护门与联锁外观检查→②急停按钮状态确认→③防护窗/外壳目视→④零件与刀具检查→⑤门联锁功能验证→⑥汇总判断）。每步含 序号/操作/判定标准/异常处理/引用知识ID。
- `常见错误`：≥2 条，每条含 错误/后果/纠正/引用知识ID。
- `练习任务`：任务/所需材料/完成证据 三字段。
- `考核`：题目≥2 条、评分规则≥2 条、合格线（安全关键项必须全对）、错后补学≥2 条；题目要有标准答案字段。
- `来源缺口`：所有无法用现有知识支撑的内容列在这里。
